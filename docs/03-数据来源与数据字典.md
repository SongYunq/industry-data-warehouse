## 5. 数据局限与分析适用边界

本节记录官方资料与全部 17 份文件实测核验确认的局限及适用边界：

| 已知局限与实测特征 | 对分析使用的约束 |
| --- | --- |
| 17 份文件分为三套异构体系（体系 A 五城 5—10 月主表、体系 B 3—4 月轨迹配套表、体系 C 制表符路网表） | **严禁直接拼接**：体系 B（`delivery_five_cities.csv` 等）并非体系 A 的五城汇总表，其字段名、哈希标识、投影坐标和日期窗口均不兼容；入库与建模前必须先按体系隔离 |
| 体系 A 内派件表与揽收表的片区／人员／AOI 编号各自独立脱敏；体系 B 轨迹匹配覆盖局部样本 | 实测吉林样本中 `delivery_jl` 与 `pickup_jl` 的 `region_id` 交集为 `0`，同号 `aoi_id` 仅 16 个且 14 个空间点位相距超 1 km（五城 `6,635` 个同号 `aoi_id` 中 `6,622` 个相距超 1 km），**不能直接按同号 `region_id`／`courier_id`／`aoi_id` 跨揽派表等价关联**（跨揽派仅按 `city` 与 `ds` 对齐）；体系 B 配套派件、揽收表分别仅有 `28.82%` 和 `14.23%` 的人员日期组合能匹配到 ZIP 轨迹 |

| 时间戳隐去具体年份（格式 `MM-DD HH:MM:SS`，日期列 `ds` 为 `MMDD`） | 原始接入层（ODS）按源文本保存；根据 [官方代码仓库说明](https://github.com/wenhaomin/LaDe#3-data-description)，体系 A（`delivery/*` 与 `pickup/*`）主数据时间跨度明确为 **`2022-05-01` 至 `2022-10-31`（UTC+8）**，DWD 层对体系 A 解析日期时应以此官方依据补齐 `2022` 年，而非任意指定基准年；体系 B（`0318`—`0401`）日期窗口不同，需单独核查，不混入同一日期维 |

| 派件文件 `delivery/*.csv` 不含预约时间窗字段（`time_window_start`／`end`） | 预约时间窗准时／超时率指标仅适用于包含预约时间窗的揽收子集（`pickup/*.csv`） |
