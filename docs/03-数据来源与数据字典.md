# 数据来源与数据字典

- 状态：三份 H&M 原始 CSV 已完成结构与质量盘点；项目渠道口径和客户分析字段范围已统一
- 最后更新：2026-11-17（Asia/Shanghai）

## 1. 来源与使用边界

当前数据源为 [Kaggle H&M Personalized Fashion Recommendations 竞赛](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/)。竞赛说明称训练数据提供客户跨时间购买历史及客户、商品元数据；完全相同的交易行可能表示同一商品的多次购买。竞赛规则将数据用途限定为非商业用途，包括学术研究和教育。本项目以商业经营问题作为分析设计视角，但数据实际只用于课程教育，不在仓库中发布原始数据或对外分发。

本地原始文件位于 `data/raw/hm_recommendations/`，由 Git 忽略。来源访问条件、许可记录和文件校验见 [数据源选取](12-数据源选取.md) 与 [下载校验清单](附件-数据下载校验清单.csv)。

## 2. 文件范围与粒度

| 文件 | 业务角色 | 源记录粒度 | 已核验行数 / 字段数 |
| --- | --- | --- | --- |
| `transactions_train.csv` | 购买明细事实 | 客户、日期、商品、渠道和源价格数值对应的一条商品购买记录 | 31,788,324 / 5 |
| `customers.csv` | 客户属性快照 | 一个 `customer_id` 一行 | 1,371,980 / 7 |

购买记录日期覆盖 2018-09-20 至 2020-09-22，共 734 个连续自然日。首月和末月仅覆盖部分日期。完整字段名见 [字段清单](附件-字段清单.csv)，结构和记录概况见 [数据概况](附件-数据概况.csv)，本轮值域与关联盘点见 [数据质量盘点](附件-数据质量盘点.csv)。

## 3. 字段说明

### 3.1 购买记录

| 字段 | 类型 / 含义 | 质量与口径 |
| --- | --- | --- |
| `t_dat` | 日期 | 2018-09-20 至 2020-09-22；日期范围内每天均有记录 |
| `customer_id` | 客户伪名标识 | 交易行均匹配客户表；只用于内部关联，不尝试反推身份 |
| `article_id` | 商品款式标识 | 交易行均匹配商品目录；最大源值 959461001，适合 Doris `INT` |
| `price` | 源价格数值 | 非空且大于 0；观察范围 0.00001694915254237288 至 0.5915254237288136。已复核 590 倍尺度，币种和金额定义待核实，详见本文件第 6 节 |
| `sales_channel_id` | 销售渠道源编码 | 项目统一口径：1=线下、2=线上；分析与展示保留源编码 |

竞赛说明表明完全相同的交易行可能对应多次购买。不得按整行去重；一行按一件商品购买记录计，但不把行数称为订单数。完整价格、渠道统计见质量盘点附件。

### 3.2 客户属性

| 字段 | 观察结果 | 使用边界 |
| --- | --- | --- |
| `customer_id` | 1,371,980 个唯一值，重复键 0 行 | 客户关联键 |
| `FN` | 476,930 行为 `1.0`，895,050 行为空（65.24%） | 原始字段清单保留；按项目规则从业务分析、分群和指标中舍弃，不将空值改写或解释 |
| `Active` | 464,404 行为 `1.0`，907,576 行为空（66.15%） | 保留为源字段；定义和有效时点未明确，不用于活跃、流失或营销许可分析 |
| `club_member_status` | 空值 6,062 行（0.44%）；观察到 `ACTIVE`、`PRE-CREATE`、`LEFT CLUB` | 状态来自无时间戳快照，不回填成历史时点状态 |
| `fashion_news_frequency` | 空值 16,009 行（1.17%）；另有字面值 `None` 2 行；观察到 `NONE`、`Regularly`、`Monthly` | 当前仅按源分类值保留描述性分析能力；不解释为 H&M 发送频率、泛类资讯兴趣或实际发送次数 |
| `age` | 空值 15,861 行（1.16%）；非空观察值 16 至 99 | 仅聚合分组；不作个体画像或定向，不解释为交易发生时年龄 |
| `postal_code` | 无空值，最长 64 字符 | 项目现有来源材料将其标记为哈希值；不反推地理区域或用于地图，不进入首版分析维度表 |

`FN` 按项目规定舍弃，不参与维度切片、回购指标、看板或汇报结论；`fashion_news_frequency` 可保留源值作描述性切片，但不赋予发送渠道或资讯类别解释。`Active` 同样不作为客户活跃、流失或营销许可指标。

客户属性是静态快照，渠道口径用于交易事实分类；不使用客户标记缺失率解释线上或线下购买行为。

客户数据是静态属性快照，没有属性生效日期。将其连接至 2018—2020 历史购买记录只能用于描述性分群，不能视作购买发生时的历史属性。

### 3.3 商品属性

商品表包含 `article_id`、`product_code`、商品名称、商品类型和组、图案和颜色、部门、`index`、`section`、服装组及描述字段。完整字段按源列序登记在字段清单。

全表 105,542 个 `article_id` 唯一，重复键 0 行；`detail_desc` 有 416 行空值（0.39%），最大文本长度 764 字符。目录中有 995 个商品款式没有出现在训练购买记录中，这只表示观察窗口未发现购买，不代表商品无需求、缺货或不可售。

商品款式可做更细分析：盘点发现 47,224 个不同 `product_code`，其中 23,158 组对应多个 `article_id`，最多一组 75 个；全部 105,542 行都满足整数关系 `article_id // 1000 = product_code`。这支持将 `product_code` 用作“款式族”候选聚合键、把 `article_id` 保留为具体变体键。此处是对编码结构的观察，不是竞赛方给出的字段语义定义。另有 22,352 个 `product_code` 组包含多个颜色组，9,576 组包含多个图案。

款式族不是完全一致的商品分类：314 个 `product_code` 组包含多个 `product_type_name`，96 组包含多个 `product_group_name`。款式族表现汇总时要保留这些分类冲突并允许下钻 `article_id`，不能任取一个分类代表整组。

可直接使用的商品分析维度基数包括颜色组 50、图案 30、商品类型 131、版块 56、部门 250。颜色还包括 `perceived_colour_master_name` 和 `perceived_colour_value_name`；同一视角可以比较实际颜色组、主色系、明暗值和图案，而不只按大类看销量。

商品目录没有生效日期、上下架、库存、价格历史或曝光信息。分类字段作为描述性属性分别使用；尚未证实的字段之间不强行构造父子层级。

## 4. 首轮数据质量结论

- 交易五个字段均无空值；日期和价格均可解析，价格非正行数为 0。
- 交易中 1,362,281 个不同客户和 104,547 个不同商品；客户与商品外键未匹配行均为 0。
- 客户和商品维度键均唯一；交易日期连续覆盖 734 天。
- 渠道编码 1 占购买记录 29.60%，编码 2 占 70.40%。本项目统一规定 1=线下、2=线上；按购买记录比例不能推断渠道转化率或盈利能力。
- `FN` 是源数据字段但按项目决定从业务分析中舍弃。`fashion_news_frequency` 仅保留源分类值，不据此判断资讯来自 H&M 还是泛类资讯，也不推断实际触达和活动效果。
- `Active` 的定义仍有互相冲突的二手解释，且缺乏有效日期；保留原始 1／空值，暂不作为活跃客户、流失或营销许可指标。
- 源价格仅作相对数值分布比较。禁止求和生成营收；缺少库存和曝光也意味着不能计算售罄率或转化率。
- 完全相同的交易行按竞赛说明作为可能的多件购买保留；没有把它们当作质量错误或合并。

当前数据质量结论只覆盖文件结构、空值、基础数值解析、主键唯一、交易外键覆盖、日期范围及有限值域。没有证据支持订单、退货、成本、库存、上架状态或营销效果分析。

## 5. 来源资料与项目约定

Kaggle [竞赛数据说明](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/data) 介绍客户、商品元数据和跨期交易记录；[竞赛规则](https://www.kaggle.com/c/h-and-m-personalized-fashion-recommendations/rules) 将数据用途限定为教育和学术研究。本项目统一规定 `sales_channel_id` 1=线下、2=线上，并在分析结果中保留源编码。`FN` 从业务分析中舍弃；客户资讯频率保留原始分类值，不对资讯来源作业务扩展。

## 6. 源价格尺度复核

2026-11-17 逐行扫描 `transactions_train.csv`，对 31,788,324 行共 9,857 个不同的源 `price` 核对 `price × 59,000` 与最近整数的距离。最大偏差约为 7.28 × 10⁻¹²，按 10⁻⁸ 的容差计，偏离整数的行数为 0。即 `price × 590` 全部落在两位小数的档位上，范围为 0.01 至 349.00。共有 24,740,538 条记录（77.83%）换算后尾数为 .99；最常见档位为 9.99（3,416,921 条）、19.99（3,406,538 条）和 14.99（3,266,926 条）。

该结果支持将 590 用作恢复价格档位的候选尺度。[Huang 与 Wang 的研究第 3.1 节](https://arxiv.org/html/2606.16183v1#S3.SS1)也采用相同倍数，依据为 Kaggle 社区讨论，且其定价模拟示例采用 USD 作展示单位。公开可核对的 H&M 竞赛说明未给出适用于这批记录的换算公式或币种。两位小数和常见定价尾数无法确定交易市场、币种或是否为实收。项目保留原始 `price`，展示换算值时使用「价格档位（源值 × 590）」。课程举例若需要币种，可写「9.99 USD（演示假设）」。分析和展示口径见 [W04 指标口径](02-需求分析.md#4-指标口径)。

商业指标口径由 [需求分析](02-需求分析.md) 维护；逻辑模型见 [逻辑设计](05-逻辑设计.md)。
