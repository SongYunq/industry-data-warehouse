### 5.1 固定版本与获取策略

- Python 环境以表中版本为实现起点，计划在 Pixi 中维护 `osx-arm64` 与 `win-64` 两个平台的依赖结果；间接依赖由实施阶段产生的锁文件固定。若渠道缺少指定补丁，先记录差异并调整文档，不静默更换版本。[Pixi 配置说明](https://pixi.prefix.dev/latest/reference/pixi_manifest/)
- Docker Desktop 采用目标系统仍受支持的稳定发行；现有客户端 29.7.2、Compose v5.5.1 仅为本机参考，不伪称服务端已安装或已验证。主机工具和服务端精确版本在后续验收记录。
- 项目服务使用明确版本的镜像并在获取后记录摘要，不能把浮动 `latest` 作为可复现交付依据。实际镜像标签取自官方发布资料，不能仅凭版本号拼接猜测标签。
- Doris 优先使用同版本且架构明确的官方镜像；若对应架构缺少现成镜像，按官方运行镜像构建说明，使用同版本官方二进制分别准备 ARM64 与 AMD64 镜像。二进制版本存在不表示某个镜像标签已存在。[官方构建说明](https://github.com/apache/doris/blob/master/docker/runtime/README.md)
- Metabase 驱动从上列发布来源获取，校验后放入计划目录 `deploy/plugins/`。使用发布 JAR 不要求宿主机安装源码构建工具；只有确需修复或构建驱动时，才按上游 Java／Clojure 要求单独处理。
- Metabase 0.64.4 与驱动 v1.0.0 是待联调的实施基线。驱动上游旧版本测试不能证明此组合已兼容；优先执行驱动加载与查询检查，失败时记录接口差异并在受支持系列内修正，不自动降到已停止支持的旧系列。

上述为明确的实施起点与调整边界，不是已通过的兼容性声明。当前不拉取镜像、不下载驱动、不构建二进制。
