实际实施前应核对所选版本的系统要求、处理器架构和镜像标签；Docker 可用与某个项目镜像可启动是不同检查。Windows 所需容器后端、系统版本和资源分配须写入实际环境记录。

## 4. 拟定服务、连接与配置

首版拟采用本地一套 Doris FE／BE，加上 Metabase 和独立 PostgreSQL；不是多机高可用部署。Python 程序与 Streamlit 在本机 Pixi 环境中运行。

| 组件 | 运行位置 | 拟定访问方式 | 后续必须检查 |
| --- | --- | --- | --- |
| Doris FE | Docker | 本机查询 `127.0.0.1:9030`；HTTP `127.0.0.1:8030` | FE 状态、查询连接、BE 注册与通信 |
| Doris BE | Docker | 本机导入 HTTP `127.0.0.1:8040` | BE 状态、实际导入地址与节点可达性 |
| Metabase | Docker | 浏览器 `http://127.0.0.1:3000` | Doris 驱动加载、Doris 连接与应用数据库连接 |
| PostgreSQL | Docker | 仅容器内部网络，由 Metabase 连接 | 初始化、账户权限和持久化；不向宿主机发布端口 |
| Streamlit | 本机 Pixi | 浏览器 `http://127.0.0.1:8501` | 本机监听、Doris 连接与错误展示 |

端口仅为方案默认值；发生占用时通过配置调整，不要求使用者直接改程序。对外发布的服务端口均绑定本机回环地址；容器间使用内部服务名通信，不能在 Metabase 容器中把 `127.0.0.1` 当作 Doris 或 PostgreSQL。

Stream Load 必须单独核查本机到实际导入节点的访问路径。若请求经过 FE，需检查其返回的 BE 重定向地址能否从本机访问；不能仅验证查询端口，也不能盲目跟随容器内部地址。直连已映射的 BE 端点是否适用于所选版本，应在实施检查中确认。

### 4.1 配置变量计划

| 变量类别 | 拟定变量 | 说明 |
| --- | --- | --- |
| 路径 | `DATA_DIR`、`MANIFEST_DIR`、`LOG_DIR` | 默认分别对应 `data/raw/`、`data/manifests/`、`logs/`，支持改到其他位置 |
| 数据源获取 | `LADE_BASE_URL`、`LADE_SOURCE_URL`、`LADE_DEFAULT_FILE`、`LADE_DATASET_FILES`、`LADE_DOWNLOAD_TIMEOUT` | 官方仓库解析根地址、默认单文件地址与相对路径、全量 17 份数据文件相对路径清单及流式下载超时秒数 |
| Doris 查询 | `DORIS_HOST`、`DORIS_QUERY_PORT`、`DORIS_DATABASE` | 本机程序使用的查询目标，实际数据库名由初始化方案确定 |
| Doris 导入 | `DORIS_LOAD_URL`、`DORIS_LOAD_TIMEOUT` | 记录实际可达端点和超时；不与查询端口混用 |

| Metabase 管理员凭据 | `MB_ADMIN_EMAIL`、`MB_ADMIN_PASS` | 必填配置项（代码与 `.env.example` 不保留固定默认密码），用于 Metabase 管理员登录与首次引导，日志自动脱敏 |
| Metabase 配置库 | `MB_DB_TYPE`、`MB_DB_HOST`、`MB_DB_PORT`、`MB_DB_DBNAME`、`MB_DB_USER`、`MB_DB_PASS` | 连接独立 PostgreSQL，使用容器内部地址；实际值在本机配置（代码与 `.env.example` 不含固定默认密码） |

精确变量名与默认值在创建配置模板时核对，不把此表视为现成模板。版本值在技术栈文档登记，不在多份文档维护独立版本清单。

Python 程序计划使用技术栈中固定的 python-dotenv 显式加载根目录 `.env`，已存在的进程环境变量优先；Docker Compose 同样从配置获取值。不得假定 Python 会自动读取 `.env`。缺少必要值时由 `doctor` 给出具体变量名，日志不回显密码。

## 5. 数据保存与持久化计划

- 原始文件默认保存在 `data/raw/`，允许通过配置使用其他磁盘；获取记录与校验信息应与文件关联。
- Doris FE 元数据、BE 数据和 PostgreSQL 应用数据分别使用 Docker 持久化卷；卷名与路径在后续配置中固定。
- Metabase 的账户、查询和看板配置由 PostgreSQL 保存；驱动文件属于部署材料，单独保留来源与校验依据。
- 普通停止和再次启动必须保留原始文件、导入记录及数据库卷；日常任务不得默认删除卷、清空数据库或覆盖原始文件。
- 更换数据位置或迁移电脑前，分别备份原始文件、导入记录、Doris 数据及 PostgreSQL 配置库；不能以复制运行中的数据库目录代替已验证的备份恢复流程。

## 6. 命令任务与首次运行步骤

以下 Pixi 任务已在 `pixi.toml` 定义并在 Mac 验证通过（调用方式：`pixi run <任务名>`）：

| Pixi 任务 | 行为与成功条件 |
| --- | --- |
| `services-up` | 自动校验／下载 Metabase Doris 驱动，启动所需容器服务（保留既有卷），并等待 Doris FE／BE 集群就绪 |
| `services-down` | 停止项目容器，严格保留数据卷和本机文件（不附加 `-v`） |
| `services-status` | 显示项目容器服务和 Doris FE／BE 存活状态，不修改业务数据 |
| `doctor` | 默认执行**非引导诊断检查**（通过 `os.access` 检查目录可写性而不创建目录或写入 `.write_probe` 文件，不创建管理员／数据库／数据源、不触发 schema 同步，仅输出本次任务日志，并核验目标表与字段已在 Metabase 发现；未发现则返回失败）；传入 `doctor --bootstrap` 时执行首次初始化（创建目录、初始化管理员、创建 Doris 数据库、注册 Metabase 数据源并触发 schema 同步；若此时尚未执行 `db-init` 建表，完成引导与 `SELECT 1` 探活后即返回成功，建表后再同步核验字段） |
| `data-fetch` | 自动获取默认完整吉林派件文件（`delivery/delivery_jl.csv`）；支持 `--file` 指定已有本地文件或 `--all` 获取全量数据源，校验 SHA-256 后复用 |
| `data-fetch-all` | 等价于 `data-fetch --all`，按 `LADE_DATASET_FILES` 批量下载并校验全部 17 份原始数据文件至 `data/raw/`（仅落盘，不入 Doris；重试耗尽时保留未完成 `.part` 分片供下次续传） |
| `data-inspect` | 检查实际表头、编码、分隔符（支持 `--delimiter` 及自动识别 `roads.csv` 的 `\t`）、列数一致性、逻辑记录数及空串／`"nan"` 计数，对 `.zip`／`.pkl.xz` 二进制归档显式报错拦截，输出清单至 `data/manifests/inspections/` |
| `db-init` | 根据已核验表头生成 `sql/bootstrap/001_raw_lade_delivery_jl.sql` 并建表；重复执行通过 `DESC` 校验结构且不删已有数据 |
| `data-import` | 从指定原始文件序列化临时 JSON Lines 并通过 Stream Load 批量导入，记录批次清单；通过 `(target_table, sha256)` 原子锁文件拦截不同 `--batch-id` 的并发重复导入；同目标同 SHA-256 自动幂等跳过；遇状态不明且查到 0 行时先查 Doris 事务状态，若事务仍处于 `PREPARE`／`COMMITTED`／`VISIBLE` 即使传 `--abort-unknown-batch` 也严禁放行新批次 |
| `data-check` | 核对导入批次状态为 `SUCCESS`、批次清单内 `target_table` 与 `batch_id` 与当前目标一致、所检文件 SHA-256 与库内 `_source_sha256` 及批次清单一致、Doris 行数与逻辑记录数一致及各字段非空计数吻合，输出 `.check.json` |
| `dashboard` | 在本机 `http://127.0.0.1:8501` 启动 Streamlit 技术接入检查页面 |

首次运行按以下顺序执行：

1. 复制 `.env.example` 为 `.env`，填入本地非默认凭据（包括必填项 `MB_ADMIN_EMAIL`、`MB_ADMIN_PASS`、`MB_DB_PASS`），执行 `pixi install` 恢复当前平台依赖。
2. 执行 `pixi run services-up`、`pixi run services-status` 和 `pixi run doctor --bootstrap`，完成容器启动、Doris 集群就绪及 Metabase 首次管理员、Doris 数据库与数据源引导（此时目标表尚未创建，`doctor --bootstrap` 完成数据源与 `SELECT 1` 验证后返回通过）。
3. 执行 `pixi run data-fetch`（或 `pixi run data-fetch-all` 获取全量文件）获取原始文件，再执行 `pixi run data-inspect` 核验真实表头与逻辑记录数。
4. 依次执行 `pixi run db-init`、`pixi run data-import`、`pixi run data-check`，再执行 `pixi run doctor --bootstrap`（同步新建表结构）与默认诊断检查 `pixi run doctor`，完成建表、原子导入、记录数与 SHA-256 对账及 Metabase 目标表字段发现核验。
5. 执行 `pixi run dashboard` 打开 `http://127.0.0.1:8501` 查看 Streamlit 页面，并访问 `http://127.0.0.1:3000` 查看 Metabase。

Mac 首次运行、全量下载探查及代码缺陷修复回归结果见 [测试与验收](09-测试与验收.md) 用例 `I01`—`I17` 与问题记录 `P01`—`P06`。

## 7. 日常启动、更新与停止

查看已有结果时，依次使用 `services-up`、`services-status`／`doctor`（默认非引导诊断模式）和 `dashboard`，复用原有环境、镜像和数据；不自动重新下载、导入或清空数据。

需要导入时显式指定原始文件并执行检查、导入与核验任务。同一目标已成功导入的相同文件内容默认跳过；文件名相同不等于内容相同。重试复用原批次信息，状态不明且库内暂查到 0 行时先核查 Doris `SHOW TRANSACTION` 状态，不直接生成新批次重复追加。

显式重新导入必须限定文件、加载目标及替换范围，并说明既有数据如何保留或备份；不提供默认清空全库的普通入口。具体策略见 [数据处理设计](07-数据处理设计.md)。

结束使用时先停止本机 Streamlit 任务，再通过 `services-down` 停止容器；保留日志、文件、导入记录和持久化卷。删除数据属于单独操作，不混入日常停止流程。

## 8. 故障定位与后续验收

| 现象 | 实际检查入口 | 恢复边界 |
| --- | --- | --- |
| 服务无法启动或反复退出 | `pixi run services-status`、Docker 容器日志、镜像架构、资源分配、端口占用 | 修正原因后重启，保留原卷，不用删库掩盖启动错误 |
| 查询成功但文件无法导入 | `logs/data_import_*.log`、本机到 BE `127.0.0.1:8040` 的访问、导入权限 | 核实实际导入端点后重试原批次 |
| HTTP 响应成功或超时但状态不明 | `data/manifests/batches/*.batch.json`、Doris `SHOW TRANSACTION WHERE LABEL = '...'`、目标表可见行数 | 不直接视为成功，也不盲目换新批次重传；若 Doris 报告事务仍处于 `PREPARE`／`COMMITTED`／`VISIBLE`，严禁重传；仅在确认事务 `ABORTED`（或 `UNKNOWN` 时人工确认并传 `--abort-unknown-batch`）后方可发起新批次 |
| Metabase 无法发现 Doris 或字段 | `logs/doctor_*.log`、驱动加载日志、管理员凭据（`MB_ADMIN_EMAIL`/`MB_ADMIN_PASS`）、首次是否已执行 `doctor --bootstrap` | 若属首次未初始化或新建表未同步则执行 `pixi run doctor --bootstrap`；若表已建且已触发同步，重跑 `pixi run doctor` 验证字段发现 |
| 大文件下载中断后重跑 | `logs/data_fetch_*.log`、`data/raw/**/*.part` 临时文件与 `data/manifests/files/` | 未完成分片自动保留 `.part`，重跑 `pixi run data-fetch-all` 自动通过 HTTP `Range` 断点续传 |

实际运行日志统一输出在 `logs/` 目录下，已完成验证的用例（`I01`—`I17`）及发现并修复的问题（`P01`—`P06`）统一记录在 [测试与验收](09-测试与验收.md)。Mac 首轮通过后，在目标 Windows 环境复用同一份交付材料，单独核对路径、权限、架构、服务连接、导入与重启保留行为。
