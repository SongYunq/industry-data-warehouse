## 1. 首次设置 Kaggle 文件访问

1. 在 [H&M Kaggle 竞赛数据页](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/data)登录账号并接受该竞赛规则。竞赛规则限制数据用于非商业用途；本项目只用于课程作业。
2. 安装项目环境：`pixi install`。
3. 使用官方 Kaggle CLI 登录：`pixi run kaggle auth login`。也可以按 [Kaggle CLI 官方认证说明](https://github.com/Kaggle/kaggle-cli/blob/main/docs/README.md)将 API token 放到用户级配置。不要将 token 写入项目文件。
4. 下载三张核心 CSV：`pixi run data-fetch`。
5. 核对完整性：`pixi run data-check`。
6. 完整读取并盘点字段和行数：`pixi run data-inspect`。结构结果写入 `docs/附件-数据概况.csv` 和 `docs/附件-字段清单.csv`；额外质量盘点见 `docs/附件-数据质量盘点.csv`。
7. 完成首次入仓后，用 `pixi run dashboard` 查看 H&M 分析与数据接入状态。

若 Kaggle 返回 403 或权限错误，先确认网页规则接受状态和 CLI 登录身份，再重试。不要使用公开镜像绕开竞赛规则。若下载中断，删除或覆盖 `data/staging/kaggle_hm/` 中不完整压缩包后重新执行 `data-fetch`。

## 2. 常用任务

| Pixi 任务 | 用途 |
| --- | --- |
| `pixi run data-fetch` | 获取或复用 H&M 三张原始 CSV |
| `pixi run data-check` | 核验字节数和 SHA-256 |
| `pixi run data-inspect` | 读取文件结构并生成小型文档证据附件 |
| `pixi run data-load` | 核验输入、建表并全量装载 H&M |
| `pixi run data-load --month YYYY-MM` | 在维度已加载的前提下重载单个交易月份 |
| `pixi run analytics-install` | 创建或更新 H&M 业务分析视图及双语展示标签 |
| `pixi run dashboard` | 启动 H&M Streamlit 分析界面 |
| `pixi run metabase-publish --verify` | 登记 H&M 数据源、发布看板并逐张查询卡片 |
| `pixi run services-up` | 启动 Doris、Metabase、PostgreSQL Compose 服务 |
| `pixi run services-down` | 停止共享服务，不删除具名数据卷 |
| `pixi run services-status` | 查看 Compose 与 Doris 状态 |

## 3. 共享服务与首次入仓

首次启动前按 [.env.example](../.env.example) 在仓库根目录创建本机 `.env`，为 PostgreSQL 应用库设置本机密码。已有环境应沿用当前 PostgreSQL 数据卷对应的配置。运行 `pixi install` 与 `pixi run services-up`。后者会核验 Metabase Doris 驱动、启动四个容器、检查 Doris FE/BE。

| 检查 | 本机实测结果 |
| --- | --- |
| `pixi run services-up` | 复用已校验驱动并保持四个服务运行，Doris 节点与 PostgreSQL 就绪 |
| `pixi run services-status` | Doris FE/BE 均为 Alive；容器镜像使用 4.0.8，节点报告 `doris-4.0.8-rc02-bc8ea1bac6d` |
| PostgreSQL 容器健康检查与应用库 SQL | `healthy`；数据库报告 18.6，应用表可查询 |
| `curl -fsS http://127.0.0.1:3000/api/health` | 返回 `{"status":"ok"}`；Metabase 日志确认注册 `doris` 驱动 |
| 驱动文件 SHA-256 | 本机 JAR 与 [锁定值](../deploy/plugins/doris.metabase-driver-v1.0.0.jar.sha256)一致 |
| 数据卷与历史试点 | 五个项目具名数据卷保留；只读查询确认 `hk_airbnb_pilot` 仍有 10 张表 |

完成原始文件准备后运行 `pixi run data-load`，目标库为 `hm_retail_dw`，表结构见 [物理设计](06-物理设计.md)，分批加载、月度重载和数据校验见 [数据处理设计](07-数据处理设计.md)。Streamlit 从主机访问 Doris 的默认 SQL 端口 `127.0.0.1:9030`，Stream Load 使用 BE 的本机发布端口 `127.0.0.1:8040`。日常只停止服务时使用 `pixi run services-down`，该命令保留具名卷。

## 4. Metabase 数据源

本机 Metabase 地址为 [127.0.0.1:3000](http://127.0.0.1:3000)。发布命令在需要时新增名为 `H&M 零售数据仓库` 的 Doris 数据源。容器间连接使用 `doris-fe:9030`、数据库 `hm_retail_dw`、用户 `hm_metabase`、忽略的本机 `.env` 中的 `HM_METABASE_DORIS_PASSWORD`，SSL 关闭。PostgreSQL 只保存 Metabase 应用元数据。历史 Doris 数据源继续保留。

1. 完成首次入仓，运行 `pixi run analytics-install` 安装 [业务查询视图](../sql/hm_recommendations/002_analytics.sql)。
2. 首次建立独立环境时，在 Doris SQL 客户端用管理员账号执行 `CREATE USER 'hm_metabase'@'172.30.0.13' IDENTIFIED BY '<随机密码>';`，将占位符替换成本机生成的密码。再执行 [只读授权与查询队列 SQL](../sql/hm_recommendations/003_metabase_reader_grants.sql)，将该密码保存在本机 `.env` 的 `HM_METABASE_DORIS_PASSWORD`。账号语法和授权范围见 [Apache Doris CREATE USER](https://doris.apache.org/docs/4.x/sql-manual/sql-statements/account-management/CREATE-USER/) 与 [Apache Doris GRANT](https://doris.apache.org/docs/4.x/sql-manual/sql-statements/account-management/GRANT-TO/)。
3. 在本机 Metabase 用管理员账号创建属于 Administrators 组的 [Metabase API 密钥](https://www.metabase.com/docs/latest/people-and-groups/api-keys)，将密钥仅放入本机 `.env` 的 `METABASE_API_KEY`。该密钥供发布命令使用，Doris 连接使用前一步的独立只读账号。
4. 运行 `pixi run metabase-publish --verify`。命令打印看板地址并逐张执行卡片查询。展示端内容和指标见 [分析与可视化设计](08-分析与可视化设计.md)。维护双语分类词表后，重跑 `analytics-install` 刷新 Doris 展示标签，再执行发布命令验证 Metabase 卡片。

当前已从 Metabase 容器的网络环境验证该账号能读取 11 个聚合视图及展示标签视图，12 个卡片查询及月份、渠道、观察窗参数均已复核，客户维度、交易明细和带标识的辅助视图返回权限拒绝。本机 Metabase 已登记 H&M 数据源并发布看板，发布命令的 12 张卡片查询均通过。看板地址与筛选实测见 [分析与可视化设计](08-分析与可视化设计.md)。

2026-11-13 在本机 Metabase v0.64.4 实测管理员账号恢复。暂停 Metabase 服务后，以同一 PostgreSQL 应用库运行官方 `reset-password` 命令。临时容器使用动态容器地址，并通过 Java 入口直接传入管理员邮箱。随后启动 Metabase 并打开本机一次性重置页，由账号使用者设置新密码并配置发布密钥。[Metabase 管理员密码重置](https://www.metabase.com/docs/latest/people-and-groups/managing#resetting-the-admin-password)

`hm_metabase` 的默认查询组为 `hm_dashboard`，同一时间运行一个查询，最多排队 20 个，单条排队上限为 120 秒。用该账号同时提交两个三秒轻量查询，分别在约 3.5 秒和 6.5 秒完成，验证了串行执行。参数含义见 [Doris 并发控制与排队](https://doris.apache.org/docs/4.x/admin-manual/workload-management/concurrency-control-and-queuing/)。

## 5. 本机资源与排障

当前 Docker Desktop 虚拟机分配内存约 7.75 GiB。初次启动 Metabase 时 Doris FE 使用镜像默认的 8 GiB Java 堆配置，服务响应变慢且 FE 自动重启一次。保留原有数据卷并重新创建 FE 容器后，FE Java 堆初始 512 MiB、最大 2 GiB，Metabase 初始 256 MiB、最大 1 GiB。四项服务就绪后的一次 `docker stats` 快照为 FE 916 MiB、BE 1.53 GiB、Metabase 1.32 GiB、PostgreSQL 114 MiB；导入峰值未单独采集。

全量分析查询期间，BE 日志记录到存储数据页缓存约 1.25 GiB，进程驻留内存约 4.15 GiB，Docker 虚拟机可用内存约 445 MiB。一项需要再分配 64 MiB 的查询触及约 397 MiB 的系统低水位，被 Doris 取消。项目 Compose 将 BE 的 `storage_page_cache_limit` 从镜像默认 20% 调为 5%。只重建 BE 容器后，在线配置返回 5%，Doris 节点恢复 Alive，购买事实仍为 31,788,324 行，Metabase 健康检查通过。Doris 内存保护机制与参数见 [内存控制策略](https://doris.apache.org/docs/4.x/admin-manual/trouble-shooting/memory-management/memory-feature/memory-control-strategy/) 和 [BE 配置](https://doris.apache.org/docs/4.x/admin-manual/config/be-config/)。

如需调整资源配置，在 `.env` 中设置 `DORIS_FE_HEAP_MB`、`DORIS_BE_PAGE_CACHE_PERCENT` 或 `METABASE_JAVA_OPTS`，待导入和活动查询结束后通过 `pixi run services-up` 应用。遇到 Doris 低内存错误时，查看 `docker stats --no-stream` 和 BE 日志；导入失败时记录月份以便按月重载。

Windows 环境和首次从空数据卷重建仍待验证。H&M 竞赛数据仅用于课程教育和学术研究。
