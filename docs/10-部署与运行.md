## 2. 目标环境与前置条件

- 首批目标：Apple 芯片 Mac，以及 Intel／AMD Windows；Intel Mac 和 Windows ARM 不列入首批验收范围。
- 推荐物理内存：16 GB；不以支持 8 GB 电脑作为首版要求。容器资源额度和实际峰值留待实施时测量，推荐配置不等于性能保证。
- Python 在本机通过 Pixi 运行；数据库及 Metabase 等服务通过 Docker 运行。文档方案采用 Docker Compose 管理多服务。
- 首次允许联网获取依赖、镜像、驱动及原始文件；后续普通启动复用已下载内容。
- 默认仅本机访问；不在首版开放局域网或公网服务。
- 先在 Mac 验证初次构建，再单独进行 Windows 部署验收，分别记录结果。

实际实施前应核对所选版本的系统要求、处理器架构和镜像标签；Docker 可用与某个项目镜像可启动是不同检查。Windows 所需容器后端、系统版本和资源分配须写入实际环境记录。

## 4. 拟定服务、连接与配置

首版拟采用本地一套 Doris FE／BE，加上 Metabase 和独立 PostgreSQL；不是多机高可用部署。Python 程序与 Streamlit 在本机 Pixi 环境中运行。

| 组件 | 运行位置 | 拟定访问方式 | 后续必须检查 |
| --- | --- | --- | --- |
| Doris FE | Docker | 本机查询 `127.0.0.1:9030`；HTTP `127.0.0.1:8030` | FE 状态、查询连接、BE 注册与通信 |
| Doris BE | Docker | 本机导入 HTTP `127.0.0.1:8040` | BE 状态、实际导入地址与节点可达性 |
| Metabase | Docker | 浏览器 `http://127.0.0.1:3000` | Doris 驱动加载、Doris 连接与应用数据库连接 |
| PostgreSQL | Docker | 仅容器内部网络，由 Metabase 连接 | 初始化、账户权限和持久化；不向宿主机发布端口 |
| Streamlit | 本机 Pixi | 浏览器 `http://127.0.0.1:8501` | 本机监听、Doris 连接与错误展示 |

端口仅为方案默认值；发生占用时通过配置调整，不要求使用者直接改程序。对外发布的服务端口均绑定本机回环地址；容器间使用内部服务名通信，不能在 Metabase 容器中把 `127.0.0.1` 当作 Doris 或 PostgreSQL。

Stream Load 必须单独核查本机到实际导入节点的访问路径。若请求经过 FE，需检查其返回的 BE 重定向地址能否从本机访问；不能仅验证查询端口，也不能盲目跟随容器内部地址。直连已映射的 BE 端点是否适用于所选版本，应在实施检查中确认。

### 4.1 配置变量计划

| 变量类别 | 拟定变量 | 说明 |
| --- | --- | --- |
| 路径 | `DATA_DIR`、`MANIFEST_DIR`、`LOG_DIR` | 默认分别对应 `data/raw/`、`data/manifests/`、`logs/`，支持改到其他位置 |
| Doris 查询 | `DORIS_HOST`、`DORIS_QUERY_PORT`、`DORIS_DATABASE` | 本机程序使用的查询目标，实际数据库名由初始化方案确定 |
| Doris 导入 | `DORIS_LOAD_URL`、`DORIS_LOAD_TIMEOUT` | 记录实际可达端点和超时；不与查询端口混用 |
| Doris 凭据 | `DORIS_USER`、`DORIS_PASSWORD` | 按任务所需权限配置，日志中不得输出密码 |
| 浏览器入口 | `STREAMLIT_PORT`、`METABASE_PORT` | 默认本机端口；监听范围保持本机 |
| Metabase 配置库 | `MB_DB_TYPE`、`MB_DB_HOST`、`MB_DB_PORT`、`MB_DB_DBNAME`、`MB_DB_USER`、`MB_DB_PASS` | 连接独立 PostgreSQL，使用容器内部地址；实际值在本机配置 |

精确变量名与默认值在创建配置模板时核对，不把此表视为现成模板。版本值在技术栈文档登记，不在多份文档维护独立版本清单。

Python 程序计划使用技术栈中固定的 python-dotenv 显式加载根目录 `.env`，已存在的进程环境变量优先；Docker Compose 同样从配置获取值。不得假定 Python 会自动读取 `.env`。缺少必要值时由 `doctor` 给出具体变量名，日志不回显密码。

## 5. 数据保存与持久化计划

- 原始文件默认保存在 `data/raw/`，允许通过配置使用其他磁盘；获取记录与校验信息应与文件关联。
- Doris FE 元数据、BE 数据和 PostgreSQL 应用数据分别使用 Docker 持久化卷；卷名与路径在后续配置中固定。
- Metabase 的账户、查询和看板配置由 PostgreSQL 保存；驱动文件属于部署材料，单独保留来源与校验依据。
- 普通停止和再次启动必须保留原始文件、导入记录及数据库卷；日常任务不得默认删除卷、清空数据库或覆盖原始文件。
- 更换数据位置或迁移电脑前，分别备份原始文件、导入记录、Doris 数据及 PostgreSQL 配置库；不能以复制运行中的数据库目录代替已验证的备份恢复流程。

## 6. 拟定命令任务与首次实施顺序

以下为未来 Pixi 任务契约，不是现有命令；只在后续实施时创建和执行。

| 计划任务 | 行为与成功条件 |
| --- | --- |
| `services-up` | 启动所需容器服务，保留既有卷；完成后仍须检查健康状态 |
| `services-down` | 停止项目容器，保留数据卷和本机文件，不执行数据清理 |
| `services-status` | 显示项目服务和健康状态，不修改业务数据 |
| `doctor` | 检查基础工具、配置、路径、端口、服务及查询／导入连接；失败时返回明确原因 |
| `data-fetch` | 自动获取默认完整吉林派件文件；支持使用已存在的本地文件，校验后复用 |
| `data-inspect` | 检查实际表头、编码、分隔、文件完整性及记录数，输出来源与字段核验信息 |
| `db-init` | 在加载结构确定后初始化必要对象；重复执行不默认删除已有对象或数据 |
| `data-import` | 从指定原始文件批量导入，记录文件校验值、目标、批次和导入结果 |
| `data-check` | 核对导入状态、行数与必要字段信息，输出可追溯检查结果 |
| `dashboard` | 启动本机 Streamlit 应用；Metabase 由容器服务提供 |

首次实施按以下顺序展开，任一步失败先定位原因，不继续把下游记为成功：

1. 根据技术栈版本记录准备基础工具与本机配置，恢复目标平台 Pixi 环境；首次可以联网，实际凭据不写入代码库。
2. 通过 `services-up`、`services-status` 和 `doctor` 验证容器状态、内部通信及本机连接；完成 Metabase 初始化和驱动确认。
3. 运行 `data-fetch` 或指定已有文件，再通过 `data-inspect` 核验一份完整吉林派件文件；只有真实表头明确后才落实加载结构。
4. 执行 `db-init`、`data-import`、`data-check`，检查业务导入状态、加载与过滤行数，并核对可查询结果。
5. 启动 `dashboard`，打开两个本机浏览器入口确认连接；本阶段不要求正式业务指标与完整图表。
6. 记录版本、系统架构、数据校验值和各步骤结果，再检查停止与重启后的数据、导入记录和 Metabase 配置保留情况。

预期结果是环境可用、原始数据可导入并核对。具体用例与通过证据统一写入测试与验收文档，当前全部未执行。

## 7. 日常启动、更新与停止

查看已有结果时，计划依次使用 `services-up`、`services-status`／`doctor` 和 `dashboard`，复用原有环境、镜像和数据；不自动重新下载、导入或清空数据。

需要导入时显式指定原始文件并执行检查、导入与核验任务。同一目标已成功导入的相同文件内容默认跳过；文件名相同不等于内容相同。重试复用原批次信息，状态不明先核对原任务，不能直接生成新批次重复追加。

显式重新导入必须限定文件、加载目标及替换范围，并说明既有数据如何保留或备份；不提供默认清空全库的普通入口。具体策略见数据处理设计，实际参数在实现时核对。

结束使用时先停止本机 Streamlit 任务，再通过 `services-down` 停止容器；保留日志、文件、导入记录和持久化卷。删除数据属于单独操作，不混入日常停止流程。

## 8. 故障定位与后续验收

| 现象 | 计划检查入口 | 恢复边界 |
| --- | --- | --- |
| 服务无法启动或反复退出 | 容器状态与日志、镜像架构、资源分配、端口占用 | 修正原因后重启，保留原卷，不用删库掩盖启动错误 |
| 查询成功但文件无法导入 | 本机到 BE 的访问、FE 重定向、端口和导入权限 | 核实实际导入端点后重试原批次 |
| HTTP 响应成功但导入失败 | 导入业务状态、错误信息、加载与过滤行数、批次记录 | 不直接视为成功；可见性延迟先查询原状态 |
| Metabase 无法发现 Doris 或字段 | 驱动加载日志、版本组合、内部地址与账户权限 | 对照技术栈记录，不将旧版兼容证据当作当前已通过 |
| 数据或看板配置重启后丢失 | 原始路径、卷挂载、PostgreSQL 连接及初始化记录 | 先核对数据位置与备份，避免再次初始化覆盖现存数据 |

实施时补充实际日志入口、经验证的处理步骤与遗留问题；当前没有故障复现记录或已通过结论。Mac 首轮通过后，在目标 Windows 环境复用同一份交付材料，单独核对路径、权限、架构、服务连接、导入与重启保留行为。
