## 1. 首次设置 Kaggle 文件访问

1. 在 [H&M Kaggle 竞赛数据页](https://www.kaggle.com/competitions/h-and-m-personalized-fashion-recommendations/data)登录账号并接受该竞赛规则。竞赛规则限制数据用于非商业用途；本项目只用于课程作业。
2. 安装项目环境：`pixi install`。
3. 使用官方 Kaggle CLI 登录：`pixi run kaggle auth login`。也可以按 [Kaggle CLI 官方认证说明](https://github.com/Kaggle/kaggle-cli/blob/main/docs/README.md)将 API token 放到用户级配置。不要将 token 写入项目文件。
4. 下载三张核心 CSV：`pixi run data-fetch`。
5. 核对完整性：`pixi run data-check`。
6. 完整读取并盘点字段和行数：`pixi run data-inspect`。结果写入 `docs/附件-数据概况.csv` 和 `docs/附件-字段清单.csv`。
7. 查看接入页：`pixi run dashboard`。

若 Kaggle 返回 403 或权限错误，先确认网页规则接受状态和 CLI 登录身份，再重试。不要使用公开镜像绕开竞赛规则。若下载中断，删除或覆盖 `data/staging/kaggle_hm/` 中不完整压缩包后重新执行 `data-fetch`。

## 2. 常用任务

| Pixi 任务 | 用途 |
| --- | --- |
| `pixi run data-fetch` | 获取或复用 H&M 三张原始 CSV |
| `pixi run data-check` | 核验字节数和 SHA-256 |
| `pixi run data-inspect` | 读取文件结构并生成小型文档证据附件 |
| `pixi run dashboard` | 启动 W03 原始文件接入检查页 |
| `pixi run services-up` | 启动 Doris、Metabase、PostgreSQL Compose 服务 |
| `pixi run services-down` | 停止共享服务，不删除具名数据卷 |
| `pixi run services-status` | 查看 Compose 与 Doris 状态 |

## 3. Docker 内存初步估算

当前 Compose 文件没有给各服务设置独立内存上限，实际可用总内存由 Docker Desktop 分配决定。以下是 H&M 装载前的规划估算，不是实测值；目前还没有设计或实现 Doris 导入器。

| 场景 | Docker 服务总内存估算 | 说明 |
| --- | ---: | --- |
| Doris FE/BE、Metabase、PostgreSQL 全部启动，轻量空闲 | 约 4–7 GB | 实际值随 Docker Desktop 配额、Metabase JVM 堆和 Doris 缓存变化 |
| 分批导入 H&M 三张表 | 约 8–12 GB 峰值 | 假设导入器流式/分批处理；同时启动看板和其他大任务会增加压力 |
| 将 3.73 GB CSV 整体读入内存再转换 | 可能超过 12 GB | CSV 磁盘大小不等于导入峰值；解析和转换会产生额外对象与缓冲区，应避免假设整表常驻内存 |

初始建议：Docker Desktop 至少分配 12 GB，主机内存充足时分配 14–16 GB 更稳妥；若主机只有 16 GB 总内存，分配 8–10 GB 并在导入时减少其他应用/暂停 Metabase，仍需观察是否触及 Doris 内存低水位。之前香港试点装载期间，Doris BE 曾报告系统可用内存约 396 MB 并拒绝后续写入，这是当时内存不足的证据，不代表 H&M 实际峰值。

Apache Doris 官方[开发/测试环境参考](https://doris.apache.org/docs/4.x/install/preparation/env-checking/)给出 FE 8 GB、BE 16 GB；这是通用参考而非本项目本机实测。Doris 会根据容器内存约束管理 BE 进程内存，[导入和查询也会占用临时内存](https://doris.apache.org/docs/4.x/admin-manual/trouble-shooting/memory-management/overview/)。Metabase 的 JVM 堆可通过 `JAVA_OPTS` 调整，默认内存会根据运行环境估算，详见[官方内存说明](https://www.metabase.com/docs/latest/troubleshooting-guide/running)。完成 H&M 表设计和分批导入实现后，应通过 `docker stats` 与 Doris BE 内存监控记录空闲、导入峰值和查询峰值，再调整本估算。
