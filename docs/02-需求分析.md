# 需求分析

- 状态：W04 首版需求与指标口径已完成；用户已确认主题优先级，实际业务使用者信息待补充
- 最后更新：2026-11-12（Asia/Shanghai）

## 1. 分析目标

围绕 H&M 历史购买记录，提供商品与品类表现、客户重复购买日、渠道构成和时间变化分析，支持商品运营、会员运营和渠道运营讨论商品结构与客户经营机会。项目强调商业分析视角，当前用途仍限于课程教育和学术研究；Kaggle 竞赛规则不允许商业使用或转发竞赛数据。

业务问题、指标和页面形成首版设计基线；用户已确认商品／品类优先，客户再次购买日与渠道构成为辅。项目未指定真实企业或业务负责人，后续如有具体对象再补充调整。

## 2. 建议的使用者与决策场景

| 建议角色 | 希望回答的问题 | 可以支持的讨论 |
| --- | --- | --- |
| 商品／品类运营 | 哪些商品类型、商品组和版块在历史购买中占比高，结构是否随时间变化？ | 复核品类组合、观察重点款式和季节性变化 |
| 会员／客户运营 | 哪些客户分群更常在不同日期再次购买，观察首购后多久再次购买？ | 设计客户分群与后续研究假设；不能据此宣称营销活动带来增量 |
| 渠道运营 | 两个来源渠道编码的购买构成和商品结构有何差异？ | 比较渠道购买组合；渠道业务名称待核实 |
| 经营管理 | 购买件数、活跃客户和商品结构在时间上如何变化？ | 识别需要进一步核查的经营现象，不直接等同利润或因果结论 |

以上为按数据能力提出的候选使用者，不代表项目已有这些真实业务用户。

## 3. 首版范围

### 纳入

- 观察期：2018-09-20 至 2020-09-22。首尾月份不完整，跨月趋势优先比较完整自然月。
- 购买明细、客户属性快照和商品属性目录；按日期、商品属性、客户属性和 `sales_channel_id` 编码进行描述性分析。
- 商品、品类、版块、客户汇总分群、重复购买日和相对时间变化。
- 年龄采用汇总年龄段；缺失值单列为未知。`FN` 和 `Active` 缺失率高，只作可选分析并显示有效覆盖率。

### 不纳入或当前不可支持

- 订单数、客单价、购物篮件数、连带率：数据没有订单 ID。同一客户同日购买多件不能据此认定为同一订单或多笔订单。
- 营收、折扣、毛利、利润、价格弹性：源 `price` 不是已核实的货币金额，且没有成本、折扣或税费字段。
- 转化率、库存周转、售罄率、缺货率：没有访问曝光、库存、可售状态或上架时间。
- 退货率、取消率、客户终身价值、真实拉新或流失：没有退货、获客、注册时间、完整历史或经确认的生命周期阈值。
- 营销活动效果、因果影响或渠道转化：没有活动、曝光和对照组数据。
- 邮编地图或地理分群：项目现有来源材料将 `postal_code` 标记为哈希值，不反推地理位置。
- 商品图片特征和推荐模型：不属于本次数仓首版需求。

## 4. 指标口径

统一口径由本节维护；看板、SQL 和验收文档引用此处，避免各页面另行定义。

| 指标 | 计算口径 | 商业解释与限制 |
| --- | --- | --- |
| 观察购买件数 | `COUNT(*)`；每行按一件商品购买记录计 | Kaggle 说明完全相同的行也可能代表同件商品多次购买，必须保留，不按行去重；不代表订单数 |
| 活跃购买客户数 | 期间内 `COUNT(DISTINCT customer_id)` | 只表示观察期内至少有一条购买记录，不代表会员总人数或当前活跃人数 |
| 商品／品类购买占比 | 该商品或分类的观察购买件数 ÷ 当前筛选范围的总观察购买件数 | 描述购买结构，不是库存售罄率或市场份额 |
| 商品触达客户数 | 购买过该商品的 `COUNT(DISTINCT customer_id)` | 描述买家覆盖，不代表商品曝光或转化 |
| 客户观察购买日数 | 每客户 `COUNT(DISTINCT t_dat)` | 同日多行只算一个购买日；不能解释成订单数或到店次数 |
| 首次观察购买日 | 每客户在本数据范围内的 `MIN(t_dat)` | 数据开始前的购买历史未知，称“观察窗首次购买”，不称新客获取日 |
| N 日再次购买日比例 | 先按客户找到首次观察购买日；仅纳入从该日起有完整 N 日观察期的客户。分子为窗口 `[首日, 首日 + N - 1]` 内至少有 2 个不同购买日的客户，分母为有完整窗口的观察购买客户 | 首版建议提供 30／60／90 日。称“再次购买日比例”，不是订单复购率、真实新客留存或营销效果 |
| 每活跃客户观察购买件数 | 观察购买件数 ÷ 活跃购买客户数 | 客户平均购买件数，不是客单价或每单件数 |
| 渠道购买构成 | 各 `sales_channel_id` 的观察购买件数 ÷ 总观察购买件数；同时报告渠道客户数 | 当前只展示编码 1、2；名称映射核实前不称线上或线下 |
| 源价格数值比较 | 按商品、品类、渠道、时间展示源 `price` 的均值或中位数 | 只作数值分布比较；禁止求和并称为营收或实收金额 |
| 客户年龄段构成 | 年龄按 16–17、18–24、25–34、35–44、45–54、55–64、65+ 汇总，缺失单列 | 年龄来自无时间戳的客户快照；只做聚合描述，不用于个体定向 |

商品类目、版块和客户属性分群均应显示样本量；对于属性缺失的分群应明确显示未知或覆盖率。上述年龄分组是首版建议，后续可按数据分布调整。

## 5. 主要分析维度

| 维度 | 可用字段 | 首版用途 | 约束 |
| --- | --- | --- | --- |
| 日期 | `t_dat` 及派生年月、季度、星期 | 完整月趋势、季节性描述 | 仅约两年历史，不预填未核实节假日或地域季节 |
| 商品结构 | `product_group_name`、`product_type_name`、`index_group_name`、`index_name`、`section_name`、颜色与服装组 | 商品组合、分类占比、商品客户覆盖 | 商品目录没有生效期、库存或曝光，不把类别父子层级视为已核实 |
| 客户分群 | 年龄、会员状态、时尚资讯频率 | 汇总比较观察购买日和品类偏好 | 属性无历史时点；`FN`、`Active` 空值高；不做个体营销画像 |
| 渠道 | `sales_channel_id` | 比较编码渠道的购买量和商品结构 | 编码含义待权威来源核实 |
| 源价格数值 | `price` | 观察不同商品组相对数值分布 | 无货币、成本和折扣定义，不计算销售金额 |

## 6. 验收口径

1. 购买明细行数与下载文件核验结果一致，客户和商品外键均可匹配；相同行按来源规则保留。
2. 任意日期、商品、客户或渠道筛选后的购买件数等于对应明细行数；按完整月份比较，不把首尾不完整月份混作完整期间。
3. 再次购买日比例按本节完整观察窗口径计算，并能展示符合窗口条件的客户数。
4. 源 `price`、渠道编码、缺失属性和客户快照均有清楚限制说明；页面不显示伪造的营收、订单、库存或转化指标。
5. 客户和商品维度主键唯一；加载重试不重复追加历史行。
