## 1. 文件接入命令

H&M 数据工具位于 `src/hm_recommendations/`，默认处理 [H&M 数据下载校验清单](附件-数据下载校验清单.csv)中的三张核心 CSV。

| 命令 | 行为 | 当前状态 |
| --- | --- | --- |
| `pixi run data-fetch` | 调用 Kaggle CLI 获取交易、客户、商品 CSV；解包后保存至 `data/raw/hm_recommendations/`，记录字节数与 SHA-256 | 已执行；三份文件均已下载。`customers.csv` 首次遇到连接中断，单文件重试成功 |
| `pixi run data-check` | 按本地清单核对三份文件的字节数和 SHA-256 | 已执行；3/3 文件通过 |
| `pixi run data-inspect` | 完整读取 CSV，盘点记录数、列数、字段名、日期范围和列数不符行 | 已执行；3/3 结构匹配，0 行列数异常；输出见数据概况和字段清单附件 |
| `pixi run dashboard` | 启动 Streamlit 原始文件接入检查页 | 已实现；未做浏览器验收 |

只处理部分文件时，可使用 `pixi run data-fetch -- --file articles.csv`；`--file` 支持 `articles.csv`、`customers.csv` 和 `transactions_train.csv`。完整结构盘点会生成 `docs/附件-数据概况.csv` 与 `docs/附件-字段清单.csv`。

## 2. 下载、身份与完整性规则

- Kaggle CLI 从官方 H&M 竞赛数据接口获取文件；下载前需用户已登录并在 Kaggle 页面接受竞赛规则。
- CLI 下载的压缩包先写入被 Git 忽略的 `data/staging/kaggle_hm/`，仅在包内找到唯一目标 CSV 且非空后，才原子替换目标文件。
- 完成下载后，清单记录来源页、相对路径、字节数和 SHA-256。再次下载时，只有文件与清单摘要一致才复用。
- 身份令牌使用 Kaggle CLI 的用户级配置，不放进仓库配置、文件清单或输出日志。新数据未获得前，不以公开镜像绕过竞赛访问条件。
- 文件字段与记录数以 W03 实际盘点为准；旧选型材料中的规模和字段信息仅作待核对参考。

## 3. W09 接入设计基线

本地原始文件作为可重载来源；不在 Doris 中长期保存一份重复的原始大表。经检查后直接写入 [W07 物理模型](06-物理设计.md) 的事实和维度表。具体装载工具、批次切分和吞吐量须在 W09 根据 Doris 4.0.8 实例及本机内存实测后确定。

| 顺序 | 处理 | 通过条件与失败行为 |
| --- | --- | --- |
| 1 | 校验三份源文件字节数、SHA-256、字段表头和记录数 | 任一文件缺失或摘要不符即停止，不覆盖有效清单 |
| 2 | 检查必需字段、日期、数值解析、维度键唯一和事实外键 | 交易必需列无空值、日期和数值可解析、客户与商品键可匹配；维度主键重复时拒绝发布。`product_code` 下类型或商品组不一致时记录质量告警并保留到 `article_id` 粒度，不将其当成自动合并或丢弃理由 |
| 3 | 转换源类型 | `t_dat` 转 `DATE`；商品编码转整数；价格转可计算数值但不生成货币金额；客户标记和属性空值按源值保留 |
| 4 | 加载客户、商品和日历维度 | 按自然键核对写入行数与唯一值数；静态维度重载前校验，不依赖覆盖行为掩盖输入冲突 |
| 5 | 按月装载购买事实 | 月分区行数之和必须为 31,788,324；完整相同行按来源规则保留；重试采用目标分区替换或清晰批次重建，不简单重复追加 |
| 6 | 装载后校验和登记批次 | 核对总行数、日期范围、渠道编码分布、空值、外键、分区数；记录输入摘要、开始/结束时间、行数与状态。核对商品分类冲突数并保留渠道原编码；未核实含义时不转换成线上／线下 |

源交易只有日期没有时间戳；客户和商品都是无有效日期的快照。处理结果不得新增订单、退货、库存、曝光或交易时点客户属性。

## 4. 派生分析数据规则

以下为 W09 实施后的派生查询／视图规则，当前尚未在 Doris 执行或验证；首版不新增持久化汇总表。

- **客户购买日序列**：先按 `customer_id + t_dat` 聚合。保留当天源行数（购买件数）、不同 `article_id` 数和出现过的渠道编码集合，再按客户日期排序生成购买日序号、前一购买日期及间隔。多行同日记录只生成一个购买日。
- **购买日渠道状态**：客户同一天只有编码 1 或 2 中的一种时，保留该日渠道编码；同日出现两个编码时标记为混合编码日。相邻购买日切换只用两端都恰为单编码的日期，不把混合编码日强行归属某渠道。
- **第 N 次购买日回购**：从不同日期序列取第 N 和第 N+1 个日期。第 N 日距数据截止日不足 H 天的客户不进 H 日分母；再次购买定义为第 N+1 个不同日期落入 `(第 N 日, 第 N 日 + H 天]`。30／60／90 日分开计算，并输出合格客户数和实际回购客户数。
- **款式族候选和颜色分析**：订单事实逐行保留，按 `article_id` 关联目录属性，再按候选 `product_code` 汇总。分类冲突要同时保留冲突状态和具体变体下钻。颜色、图案为空时保留未知组，不得将未知静默变成无颜色或无图案。
- **客户首现月份、近期性和客户分层**：首现日仅指当前观察期首次出现的交易日。以首现月切片第 1 个购买日的 H 日回购；近期性以固定数据截止日计算，只能代表该历史观察区间。客户分群输出汇总样本数，不生成个体触达名单。
- **组合集中度和覆盖率**：商品前 10／20 份额分母为同一日期、商品分类和筛选范围内的购买件数；目录变体覆盖分母来自静态商品快照，不能表述为库存售罄或供给利用率。

派生指标的业务定义统一见 [需求分析](02-需求分析.md)；该规则是设计基线，不代表查询、视图或看板已实现。

## 5. 装载失败与恢复原则

- 下载层保留已验证目标文件；失败下载写临时文件，不以不完整文件覆盖有效源文件。
- 转换或关联门禁失败时停止该批次，保留错误摘要，不发布不完整分析结果。
- 购买事实可按自然月重载；一个月分区的失败恢复不得改变其他月份。是否采用 Doris Stream Load 或其他方式留待 W09 实机评估。
- 因合法重复行属于购买数量，重试语义必须以分区替换或批次控制保证幂等，不能依靠去重来消除重复载入。
- 禁止将 Kaggle 凭据、客户真实身份或原始大文件写入仓库、日志或清单。

源价格含义、渠道名称和邮编地理语义的边界见 [数据字典](03-数据来源与数据字典.md)；实际建表与导入尚未执行，整体状态见 [工作内容与进度](00-工作内容与进度.md)。
