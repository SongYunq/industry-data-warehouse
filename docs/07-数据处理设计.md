| Pixi 任务 | 实际输入参数 | 实际输出与成功条件 | 前置条件 |

## 4. 采集与加载

以下文件加载流程已在 `src/warehouse/data_pipeline.py` 实施并在 Mac 验证通过：

1. 获取完整真实文件，保留源地址、文件名、获取时间和文件校验信息。
2. 检查实际表头、编码、分隔与空值形式，再确定原始加载结构和必要的格式映射；本阶段不擅自增加业务清洗规则。
3. 拟通过 Doris Stream Load 批量加载文件，Python 查询客户端负责连接、核验记录数及抽查结果；查询与文件加载不是同一条连接路径。
4. 记录导入批次、文件信息、目标和返回结果。需要同时检查业务状态、加载与过滤行数，不能仅凭 HTTP 成功响应认定导入完成。

### 4.1 获取与格式处理契约

- 默认来源为吉林派件文件；已有本地文件也走同一检查流程，不能绕过文件核验直接加载。
- 下载先写临时文件，成功且完整性检查通过后再成为正式原始文件；网络中断不覆盖已有完整文件。不修改上游原始内容。
- 使用标准库 CSV 解析；编码不匹配、空或重复表头、保留列名冲突、记录列数不符时停止并报告，不能静默截断、补值或跳过。
- 加载前仅做格式序列化与附加接入元数据，源字段按原始文本保存。计划生成临时 JSON Lines 加载材料，业务空值、日期年份与业务去重不在此擅自解释。接入字段与表模型见 [物理设计](06-物理设计.md) 第 9 节。
- 首次一份小文件按一个原子导入批次处理；开启严格加载并将允许过滤比例设为零，要求成功加载记录数与文件检查结果一致。实际参数支持在所选版本下核验。
- 原始文件默认 `data/raw/`，暂存材料 `data/staging/`，文件与批次记录 `data/manifests/`，执行日志 `logs/`；位置可配置，均不纳入 Git。日志不输出密码，暂存材料不替代原始文件。

Doris 官方将 Stream Load 用于本地文件和脚本导入，可同步返回结果；具体客户端版本、请求参数和节点可达性仍待选版与联调。[本地文件导入说明](https://doris.apache.org/docs/4.x/data-operate/import/data-source/local-file.html/)

## 6. 首次加载、后续更新与重复执行

待确定全量与增量适用范围、变化识别方式、历史更正与补跑方式，以及重复执行同一批次如何避免重复或遗漏。处理频率、增量依据和相关键值均待设计，不预先指定。

针对首次文件导入，拟保存文件校验信息、加载目标和成功批次记录；默认识别同一目标已成功加载的相同文件内容，避免普通重跑静默重复追加。显式重新加载的覆盖范围与失败恢复行为需在实现前明确，不以文件名相同代替内容相同。

- 成功状态由加载结果与目标数据核对共同确定；只记录请求已发送，不能据此写入成功记录。
- 识别范围为“加载目标＋原始文件 SHA-256”，批次记录另包含来源、任务标识、编码、记录数及状态。同文件成功重跑默认跳过并说明原因。
- 正在处理或状态不明的批次禁止自动并行重传；先查询原任务和目标中的接入元数据。记录丢失时先核对目标数据，不直接换批次追加。
- 首版普通任务不提供默认覆盖、删库或全量重置；重新加载属于单独显式操作，须限定原始文件、加载目标与替换范围。原文件内容变化时保存为新来源版本并报告，不静默替换旧文件。

Stream Load 的批次标签仅在保留期内限制相同标签的重复提交；更换标签会成为新的任务，不能替代项目长期的文件重复识别。返回可见性延迟或状态不明时，应先核对原批次状态，不直接换标签重传。[Stream Load 手册](https://doris.apache.org/docs/4.x/data-operate/import/import-way/stream-load-manual/)

## 7. 质量检查与失败处理

首次接入以完整保留真实记录为目标，任何解析或加载错误均需报告；不把过滤后的部分数据标作整文件导入成功。导入成功且行数核对完成后，才记录本批次可用于后续技术查询。失败记录应包含任务、批次、阶段、错误摘要与可安全重试条件；连接和下载可作有界重试，导入状态不明时先查询再决定。
