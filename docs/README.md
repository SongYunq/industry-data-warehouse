技术栈文档可以说明某项工作采用什么工具，但不展开业务对象、事实表、维度表、具体处理规则或启动步骤，分别链接到负责该内容的文档。

## 维护规则

1. 发生实际进展时，同步更新工作进度和直接相关的阶段文档；结束当次工作前完成更新。
2. 明确区分“已确认”“建议／候选”“待确定”和“已验证”；引用上游资料不能替代项目验证。
3. 暂无结论的章节保留“待补充”，不使用假业务数据、示例版本或推测结果填满文档。
4. 状态变化必须有产出或证据；不以文档数量推算项目完成百分比。
5. 修订已确认内容时，先更新所属文档，再检查引用文档和实现是否需要同步；重要变化记入进度记录。
6. 已解决的事项应更新为结论并保留必要依据，不长期保留过期的“待确定”。
