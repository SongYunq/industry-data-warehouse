## 输入和转换

四个快照目录各读取 `listings.csv.gz`、`calendar.csv.gz`；只从最新快照读取累积 `reviews.csv.gz`，并从最新 `neighbourhoods.geojson` 读取街区边界。评论文本和评论者标识不进入处理结果。

1. 目录日期形成 `snapshot_date`；房源 `id` 转 BIGINT，无效房源主键使当前装载失败。
2. 数值按目标类型转换，空串或解析失败转 NULL；挂牌价去除货币符号与千位分隔符；房东回复率字段去除 `%` 后存百分比数值。
3. 街区优先取 `neighbourhood_cleansed`，缺失时回退 `neighbourhood`。
4. 房东公开属性按房东×快照去重，保留超赞房东、身份验证、加入日期、房源数和回复/接受率；姓名、简介与图片不读入目标表。
5. 房态 CSV 逐行流式读取，以快照、入住日、街区、房型、房屋类型分组；记录可订、不可订和未知状态计数。
6. 最新累积评论文件按评论日期的月份分组，计数评论和不同房源，并记录月内日期范围；不把各期累积导出相加。
7. 生成覆盖评论月份与日历日期范围的 `dim_date`，维度日期均以自然日期键记录。

本地核数结果：房源 22,093 行、18 个街区、4 种房型、73 种房屋类型；日历源记录 8,072,340 行汇总为 344,830 行；最新评论文件 122,715 行汇总为 188 个月度记录。此验证来自本地 CSV，不代表 Doris 已全量写入。

## Doris 装载与恢复

命令：

```bash
pixi run data-load-hong-kong
```

装载采用每批 200 行的 `executemany`。所有维度和事实均用 Doris UNIQUE KEY；意外中断可直接重跑，已完成键会覆盖，其他库表不受影响。此策略不会自动删除来源后续撤回的旧键，若来源内容变化需显式清理对应专属表再重载。

本次实际启动 Docker Desktop 后确认 FE、BE 在线，十张表均建成。装载期间第一期的 1,568 个房东维度和 5,000 个日历汇总行已写入；BE 随后报告系统可用内存约 396 MB，低于分配阈值并拒绝新分配。Doris 房源表行数查询也因相同内存限制失败。库内因此存在部分数据；不可用它做完整看板，也没有把装载标记为通过。资源可用后重跑同一命令，再对照每期房源 6,630／2,115／6,734／6,614、全部街区 18 个、日历摘要和评论摘要基线。

## 看板数据模式

- `HK_PILOT_DATA_MODE=auto`：先读 Doris 并验证四期房源基线、街区数和汇总事实；不完整时使用本地数据。
- `HK_PILOT_DATA_MODE=warehouse`：强制使用 Doris；查询或完整性检查失败时显示错误。
- `HK_PILOT_DATA_MODE=local`：仅读本地源 CSV，并在本地流式聚合日历与评论。

日历本地回退会为每期房源建立约 6,000 条的维度映射，再逐行扫描 800 多万条压缩日历记录，内存只保留聚合键和值；评论回退只处理最新文件必要字段。应用缓存 10 分钟，避免每次交互重扫原始文件。
