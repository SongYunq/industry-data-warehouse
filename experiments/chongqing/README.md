# 重庆末端揽派数仓实验

最后更新：2026-11-12（Asia/Shanghai）

本实验使用 LaDe 重庆真实数据，在独立的 Doris `cq_pilot` 库中验证从原始来源到业务分层再到 Streamlit 看板的流程。实验使用 Streamlit 展示结果，独立于原项目的吉林接入和 Metabase。验收状态以本文的运行记录为准。

## 需求与范围（W04）

末端运营主管用看板复盘揽派完成量、耗时、预约表现及片区和人员的作业负荷。物业和驿站规划视角可查看脱敏末端区域及完成高峰。无人车与市政规划视角可查看轨迹样本和道路结构，为后续现场核查提供线索。数据是历史样本，站点实际归属、当前配送状态、交通流量和无人车通行条件均需要单独的来源。

| 专题 | 分析口径 |
| --- | --- |
| 完成量与履约 | 分揽收、派件统计。揽收按 `pickup_time` 的日期和小时，派件按 `delivery_time` 的日期和小时。耗时从接单到完成，异常耗时单独识别。 |
| 揽收预约 | 按时履约指完成时间不晚于预约截止，包含提前揽收。窗内命中包含起止边界。提前指早于预约开始，超时指晚于截止。派件源表没有预约时间窗。 |
| 区域、人员与定位 | 片区、快递员、末端区域（AOI）按业务分别统计；活跃作业日指有完成记录的日期。接单与完成定位分别报告有效覆盖，偏移仅统计目标点和打卡点均有效的记录。 |
| 轨迹与路网 | 轨迹按采样日期及匹配到的匿名人员观察。道路专题按源路段记录统计等级、方向、桥梁和隧道。轨迹使用原始相对坐标，道路和订单点能否叠加需另行核验坐标口径。 |

## 概念和逻辑设计（W05—W06）

| 来源 | 业务对象和分析粒度 | 关联边界 |
| --- | --- | --- |
| A · `delivery/delivery_cq.csv`、`pickup/pickup_cq.csv` | 一行是一条派件或揽收记录，包含接单、完成和相应的事件打卡。原始核查为派件 931,351 行、揽收 1,172,703 行。 | 公共汇总用城市、完成日期。片区、人员、末端区域编号按业务隔离，不能用揽派同号编号匹配实体。 |
| B · 根目录配套揽派表、`courier_detailed_trajectory.zip` | 配套表一行是一条订单；轨迹一行是某匿名人员在某日的一次定位采样。按两张配套表的匿名人员和日期匹配，并仅保留可唯一归属重庆的轨迹点。 | 配套订单及轨迹观察期为 3—4 月。标识和坐标口径与体系 A 不同，分别统计且单独报告匹配覆盖。 |
| C · `road-network/roads.csv` | 一行是一条道路记录。按 `重庆市` 筛选，并保留道路属性及原始几何文本。 | 静态道路记录独立于订单和轨迹；道路等级与方向使用源值。 |

主表保留 `ds` 供来源核对，分析时间按体系 A 的官方年份 2022 和中国标准时间解析。揽派共享城市和时间维度，业务内可按片区、人员或末端区域下钻。时间窗与定位质量标记在明细处理阶段计算，避免页面筛选后改变指标定义。轨迹的日期、匿名人员和道路标识各用其源体系口径。来源覆盖和原始实测见[数据来源与数据字典](../../docs/03-数据来源与数据字典.md#46-轨迹与路网覆盖和处理规模核查)。

重庆两份主表的源 `ds` 均落在 5—10 月。独立检查发现派件实际完成日有 775 条落在这段范围外，其中 1 月 3 条、11 月 760 条、12 月 12 条。按实际完成日筛选时以页面的日期范围为准，源日期仅用于来源核对。揽收实际完成日全部落在 5—10 月。

## Doris 实现与运行（W07）

本地准备阶段读取 `data/raw/` 中的原始文件，把重庆范围的规范化结果写入 `data/chongqing/prepared/`。原始文件承担源层留存；Doris 的实验库按以下粒度保存清洗明细和专题结果。Streamlit 通过 Doris 查询已发布的数据。

| 表 | 粒度与职责 |
| --- | --- |
| `dwd_orders` | 一条揽收或派件订单。保留业务类型、订单、片区、人员、末端区域、完成日、预约分类、定位偏移、源日期和源行号。 |
| `dws_daily` | 一类业务在一个完成日的汇总。保存单量及耗时、定位、预约统计所需的计数与总量。 |
| `b_orders`、`b_trajectory_points` | 一条配套揽派订单或一条可唯一归属重庆的轨迹点。保留对应文件或归档成员的源行号。 |
| `b_trajectory_days`、`b_coverage`、`b_sample_polylines` | 分别按匿名人员和日期、业务类型、样本轨迹点保存结果。样本按每类业务的人员日采样点数选择，按时间和源行号排序；最多每条 480 点，保留首尾。 |
| `c_roads`、`c_road_classes` | 一条道路记录或一个道路类别。道路明细保留源几何文本，汇总记录方向、桥梁、隧道等属性。 |

发布读取同名 CSV 与 `.schema.json`，以小批次写入候选表，核对字段和记录数后再替换 `cq_pilot` 中的同名表。实验使用单副本和随机分桶。每张表独立切换，发布过程按顺序执行，建议等整次发布与核验完成后再打开看板。

从仓库根目录运行。先打开 Docker Desktop，准备已有的项目 `.env` 和 `data/raw/`；首次使用时可先执行 `pixi install`。实验读取 `.env` 或当前环境中的 Doris 用户、密码及端口。查询和加载默认使用本机 `9030` 和 `8040`。以下 Compose 命令仅启动 Doris FE、BE，并复用已有容器和数据卷。

```sh
docker compose --env-file .env -f deploy/compose.yaml up -d --no-recreate doris-fe doris-be
pixi run python -m experiments.chongqing.prepare
pixi run python -m experiments.chongqing.warehouse publish
pixi run python -m experiments.chongqing.warehouse verify
pixi run python -m streamlit run experiments/chongqing/app.py --server.address 127.0.0.1 --server.port 8510
```

在浏览器访问 [重庆末端揽派看板](http://127.0.0.1:8510)。已有发布结果时，日常只需保证 Doris 正在运行，再执行最后一条命令。结束页面服务可在启动终端按 `Ctrl+C`。首次准备会读取完整的配套表、轨迹归档和路网，再筛选重庆；本地暂存和 Doris 占用会超出原始压缩文件体积。

## 运行与验收记录

本地独立复算已核对重庆两份主表，得到以下 Doris 发布后的对账基准。

| 检查口径 | 源文件复算值 |
| --- | --- |
| 订单明细 | 派件 931,351 单，揽收 1,172,703 单，两份文件内 `order_id` 分别无重复 |
| 2022-06-01 实际完成量 | 派件 6,606 单，揽收 5,582 单 |
| 揽收预约 | 1,172,703 条有效预约，提前 249,929、窗内 897,810、超时 24,964；窗内含恰好开始 7,128 和恰好结束 838 条 |
| 揽收定位 | 接单坐标有效 625,363 条，完成坐标有效 849,961 条 |
| 轨迹配套 | 配套派件 121,247 单、揽收 114,463 单；唯一归属重庆的轨迹点 2,345,953 条 |
| 轨迹覆盖 | 按业务分别计人员日：派件 1,737 / 6,176，揽收 2,352 / 12,746 |
| 道路 | 121,976 条道路记录、25 个道路类别；其中 `LINESTRING` 121,895 条、`MULTILINESTRING` 81 条 |

准备结果由 `data/chongqing/prepared/orders_manifest.json` 和 `spatial_manifest.json` 记录。轨迹样本坐标以首点为原点，沿用源轴与源单位。路网源文件未声明坐标参考系，几何只能作源坐标示意或经明确假设的近似展示。订单点与道路的空间匹配不计入本次验收。
